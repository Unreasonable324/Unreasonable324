### About

I build large, long-lived products: corporate ERP systems, government information systems and e-commerce platforms.

Owned the client-side architecture of an **ERP platform with 28 business modules** and worked on the **Russian Federation open data portal** (`data.gov.ru`). What I'm good at: reusable infrastructure (forms, tables, filters, data layer), access control systems (RBAC), real-time over WebSocket, SSR apps on Nuxt and client-side performance. I also run code reviews, tech interviews and mentoring.

Came into development from the restaurant industry — worked my way up from cook to head chef. Still cooking, just not for a living.

### Selected work

<details>
  <summary><b>ERP platform — 28 business modules</b> · Vue 3, Nuxt 3, Pinia, TanStack Query, WebSocket</summary>

  <br>

  Automation of internal business processes: finance, CRM, logistics, HR, RBAC, user action audit. Used by commercial, client-facing and management departments.
  Lead frontend engineer and owner of the client-side architecture — **800+ closed tasks in 26 months**, average time from ticket to release 2.3 days.

  - Defined the architectural standard for a business module — layer structure, public Pinia store contract, business logic isolation rules, engineering docs. A new module starts from a ready skeleton instead of copy-pasting a neighbour; applied across all 28 modules.
  - Designed the RBAC system end to end — from routing and middleware down to individual UI actions — plus an audit module for 30 business entity types with nested relations.
  - Real-time layer on WebSocket for chat and events with reconnection, message buffering and channel routing — 7 modules exchanging data at **88ms** average delivery latency.
  - Forms infrastructure on VeeValidate with reusable composables and centralized business validation — covers **42 forms**, new form implementation went from 6h to 1.5h.

</details>

<details>
  <summary><b>Novex</b> — federal retail chain, 300+ stores · Nuxt SSR, Nitro, ISR</summary>

  <br>

  <a href="https://novex.ru">novex.ru</a> — responsible for the SSR catalog and client-side performance.

  - Moved key catalog sections from client rendering to SSR, set up meta tags, Open Graph and Schema.org for 300+ store pages — **LCP 3.7s → 1.4s**, Lighthouse SEO score **71 → 98**, catalog indexing up **2.3×**.
  - Granular SSR response caching and ISR for product cards on Nitro server routes — average server response **640ms → 118ms** at half the API load; the catalog held peak sale traffic without degradation.

</details>

<details>
  <summary><b>Greenway Global</b> — international e-commerce · Nuxt SSR, nuxt-i18n</summary>

  <br>

  <a href="https://greenwayglobal.com">greenwayglobal.com</a> — responsible for storefront SSR, localization and SEO infrastructure.

  - Multi-language storefront on nuxt-i18n with separate SSR routes and hreflang markup — removed duplicate language versions from the index, organic traffic from non-Russian regions grew **19% → 34%**.

</details>

<details>
  <summary><b>data.gov.ru</b> — Russian Federation open data portal · Vue 3, FSD, PWA, STOMP</summary>

  <br>

  <a href="https://data.gov.ru/">data.gov.ru</a> — an ecosystem of several apps (public portal, PWA, admin services) covering 15+ business domains: open data catalogs, BI analytics, data supplier account, legal acts, discussions, chatbot, news.

  - Designed the data layer with caching, TTL invalidation and cursor pagination serving 12 domain entities — removed ~**3140 lines** of duplicated request logic, API calls on typical screens down **57%**.
  - Split the codebase into Feature-Sliced Design layers with public slice APIs — new domain modules plugged in without touching existing ones, which killed the merge conflicts between five frontenders.
  - Built 3 internal npm packages (UI kit, HTTP client, format utils) in a pnpm workspaces monorepo — starting a new service went from 2 weeks to 4 days.
  - OAuth 2.0 auth via ЕСИА (Gosuslugi) with full account confirmation status handling — successful logins **82% → 97%**.
  - Real-time chatbot on STOMP/SockJS with personal channels and voice input via Web Speech API — up to **1180 dialogs/day** at 137ms average delivery.
  - Accessibility pass on public sections (semantic markup, ARIA for catalog tables, full keyboard navigation, low-vision mode) — passed the pre-certification audit with no findings; axe-core in CI keeps critical violations at zero.
  - Streaming download of large datasets via Streams API with progress and resume — hundred-megabyte files stopped killing the browser tab, successful downloads **74% → 98%**.

</details>

<details>
  <summary><b>Cargo transportation platform</b> · Vue + Vite, Axios, Django, PostgreSQL, Redis</summary>

  - Dynamic SEO service pages pre-generated from the destinations reference, with meta tags and Schema.org markup — **340 pages indexed instead of 27**, Lighthouse SEO **68 → 96**, organic traffic to service sections up **2.7×** in 4 months.
  - Delivery cost calculator computing across 9 parameters client-side, with tariff references cached in localStorage with TTL — API calls per session **14 → 3**.
